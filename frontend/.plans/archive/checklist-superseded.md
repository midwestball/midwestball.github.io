## The Knowball & Ballnet Architecture

### 1. The `ballnet` Backend (Private / Local)

This is your private sandbox. It has no direct interaction with the end-user.

* **The ETL Pipeline:** Python scripts that pull from `nflverse`, calculate the raw stats, apply the ramp-and-hold sample size logic ($\min\_n = n_{\text{base}} \times \min(w, 4)$), and compute the coordinates for the KDEs and Histograms. It pushes these finished JSON payloads to Supabase.
* **The ML Engine:** Local Python training and inference scripts. You run these locally to generate player projections, interaction matrices for the draft, and positional value curves. The output is pushed to Supabase as flat, easily queryable tables (e.g., `draft_projections_2026`).

### 2. The Data Bridge (Supabase)

* **Leg 1 (Public Data):** Contains tables like `player_bios`, `weekly_stats`, and `distribution_curves`. These are configured with open Row Level Security (RLS) policies for read-only public access.
* **Leg 2 (Premium Data):** Contains tables like `draft_interaction_matrices` and `user_profiles`. These RLS policies require an authenticated Clerk token and a verified Stripe subscription status to read.

### 3. The `knowball` Frontend (Public / Vercel)

This is the Next.js application that users actually see. It is completely decoupled from the data generation process.

* **Public Visualization Routes (`/stats`):** Fetches the precomputed KDE and Histogram JSONs from Supabase. Renders the `<ExpandableStatRow>` components using Observable Plot. Handles the logic to read the "Zero mass" flags from your schema to ensure charts clip at zero correctly.
* **Authentication & Billing:** Integrates Clerk for user sessions and Stripe for paywalling the Leg 2 features.
* **Live Draft Optimizer (`/draft-assistant`):** A client-side React application that maintains the state of the user's current draft board. Every time a player is drafted, it queries the precomputed `draft_interaction_matrices` in Supabase to instantly render the next recommended picks or trades.

## The `knowball` Implementation Checklist

This checklist acts as your roadmap for the frontend repository, ensuring you build the foundation before getting distracted by the shiny UI elements.

### Phase 1: Foundation & Data Fetching

* [ ] **Initialize Next.js:** Scaffold the `knowball` Next.js (App Router) project with Tailwind CSS and TypeScript.
* [ ] **Configure Supabase Client:** Install the `@supabase/supabase-js` library and set up your environment variables (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
* [ ] **Implement the Base API Hooks:** Create server actions or React Query hooks to fetch the `player_stats` and `distribution_curves` tables from Supabase.
* [ ] **Data Mapping Utility:** Write a utility function that parses the data types specified in your markdown document (e.g., knowing that "Passing Yards" uses a continuous KDE bounded at 0, while "Passing TDs" uses a discrete Histogram with high zero mass).

### Phase 2: Building the Leg 1 Visualizations

* [ ] **Scaffold the Component Library:** Install `shadcn/ui` and initialize the Accordion and Slider primitives.
* [ ] **Build `<ExpandableStatRow>`:** Create the core interactive component. Connect the Slider to the player's percentile rank.
* [ ] **Integrate Observable Plot:** Build the charting sub-components.
* [ ] Create a `<KDEChart>` component that accepts the precomputed JSON coordinates and renders an `areaY` plot. Ensure it respects the zero-bound constraints.
* [ ] Create a `<HistogramChart>` component for discrete stats using `rectY` with the fixed bins generated by `ballnet`.


* [ ] **Implement the Ramp-and-Hold Filter:** Add frontend UI logic that greys out or disables the slider for a specific stat if the player's volume has not met the threshold defined by the formula ($\min\_n = n_{\text{base}} \times \min(w, 4)$).

### Phase 3: Leg 2 Paywall & User Management

* [ ] **Integrate Clerk:** Wrap the Next.js app in the `<ClerkProvider>` and set up the `/sign-in` and `/sign-up` routes.
* [ ] **Stripe Webhooks:** Create a `/api/webhooks/stripe` route in Next.js to listen for successful payments.
* [ ] **Sync Auth with Supabase:** Configure Clerk to pass custom JWTs to Supabase so that your Row Level Security (RLS) policies know if the current user has `is_pro: true`.
* [ ] **Gate the Premium Routes:** Use Next.js Middleware to protect the `/draft-assistant` and `/optimizer` routes, redirecting unpaid users to a pricing page.

### Phase 4: The Draft Optimizer MVP

* [ ] **Build the Draft Board State:** Create a React Context or Zustand store to hold the live state of a draft (who has been picked, current roster).
* [ ] **Connect the Precomputed Matrices:** Write the query that fetches the optimal next picks from your premium Supabase tables based on the current draft board state.
* [ ] **Build the UI:** Render the optimal picks, positional value drop-offs, and interaction matrix recommendations in a clean dashboard.
